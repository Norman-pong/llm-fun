# T3 讲解笔记：BPE 分词器

## 问题

- 模型只认整数 id，字符串怎么变成 id？为什么不用「字符」或「单词」做单位？
- 中文/emoji 怎么办？为什么 BPE 不会有未知符号？

## 1. 为什么是「字节对」

三个候选方案的困境：

| 方案 | 词表大小 | 问题 |
|---|---|---|
| 字符级（27/几万个） | 小 | 序列太长，模型要看很远才能拼出一个词 |
| 单词级 | 爆炸 | 开放词表：新词、拼写变体、中文组合全是 OOV |
| **字节级 BPE** | 可控（自己定） | **256 个字节覆盖一切 UTF-8 文本，永远没有未知符号** |

BPE 的训练就是一句话：**反复把最高频的相邻 id 对合并成一个新 id**，直到词表到目标大小。
高频片段（如英文的 `th`、`ing`、人名语料里的 `anna`）自动长成 token；
罕见内容自动退化为更多字节——词表大小与序列长度之间的滑块。

## 2. 实现结构（tokenizer.py）

```
get_stats(ids)  : Counter(相邻对)
merge(ids, p, nid): 顺序扫描替换（不重叠回吃）
train : 循环 选最高频对 → 合并 → 记入 merges（插入序=优先级）→ 更新 vocab
encode: 反复应用「最早学到的」可合并对（贪心按优先级）
decode: id 串 → bytes 拼接 → utf-8 解码
```

两个决定可复现性的细节：

- **同频平票的确定性**：`max(stats, key=lambda p: (count, p))`——同频取 pair 字典序，
  而不是依赖 dict 遍历顺序。toy 语料 `aaabdaaabac` 全程可手算（见测试）。
- **合并不回吃**：`merge` 是从左到右一次扫描，`aaaa` 中 (97,97) 合并两次、不会产生连锁。

## 3. Pre-tokenization：为什么 GPT-2 要先正则切块

不做切块，BPE 会把「跨词边界」的高频拼接学成 token。实测（names.txt，词表 512）：

- **BasicTokenizer** 学到的 token：`'ah\n'`、`'an\n'`、`'na\n'`——把「词尾+换行」
  焊在一起，编码与解码都没错，但这种 token 对语言建模是有害的噪声。
- **RegexTokenizer**（GPT-2 正则 `\s?\p{L}+` 等）学到的：`'ari'`、`'ana'`、`'lyn'`、
  `'anna'`——全是词内片段，干净。

代价：压缩率从 49.75% 降到 58.62%（块内统计更碎），换来 token 的语义整洁，值得。

正则本身值得读一遍（`GPT2_SPLIT_PATTERN`）：缩写 `'s`/`'re`、可选前导空格的字母串
` ?\p{L}+`、数字串、标点串、空白组——**「空格属于后面的词」** 是 GPT-2 一脉的关键设计，
它让 token 自带词界信息。

## 4. 实测数据（names.txt 228145 字节，词表 512）

| 分词器 | tokens | 压缩率 | 例子 |
|---|---|---|---|
| Basic | 113511 | 49.75% | `emma → [302,109,97]`（302=`em`） |
| Regex (GPT-2) | 133745 | 58.62% | `emma → [305,279]`（`emm`+`a`）、`kaiden → [357,334]` |

`你好世界` 在英文人名语料下退化为 12 个原始字节——**BPE 的词表由语料决定**，
中文模型的词表必须用中文语料训练（这正是 Qwen/GLM 词表动辄 15 万+ 的原因）。

## 5. 踩坑

- `zip(ids, ids[1:], strict=True)` 是 bug：两列天然差 1，strict 必炸；等长列表才配 strict。
- 测试预期「空格保持独立 token」是错的——GPT-2 正则里 ` ?\p{L}+` 把前导空格划进词块，
  `" ab"` 整体成为 token 是**正确**行为。写测试前先把正则语义手推一遍。
- RegexTokenizer 训练全程必须操作 id 列表；中途解码回字符串会破坏多字节 UTF-8 字符。

## 6. 与后续章节的衔接

- T4/T5 的 mini-GPT 用字符级词表（65 个）回避分词复杂度，专注架构本身；
  真实规模模型（T8 minimind 路线）才把本章的 BPE 接进训练管线。
- vocab 大小 = embedding 矩阵的行数 = 输出 softmax 的类数：分词器直接决定模型参数量。
