# T2 讲解笔记：语言建模——从数频次到嵌入

## 问题

- 语言模型到底是什么？——**P(下一个字符 | 前文)**，一个巨大的条件概率分布
- 为什么数频次的 bigram 不够用，神经网络带来了什么？

## 1. 语言模型的最小定义

给定词表 `itos = ['.', 'a', ..., 'z']`（27 个字符，'.' 兼作起止符），每个名字
`"emma"` 展开成 5 个样本：`(...)→e, (..e)→m, (.em)→m, (emm)→a, (mma)→.`
模型要学的就是每个箭头处的条件分布。训练目标 = 最小化平均负对数似然（NLL），
等价于交叉熵。**均匀分布基线是 ln(27)≈3.30，任何模型先和它比。**

## 2. 基线：bigram（数频次）

`P(b|a) = count(a,b) / count(a)`，加 1 平滑避免零概率。没有可学参数，
context 只有 1 个字符——**「e 后面是 m」和「前面的字符是 m」在它眼里无关**。

实测（names.txt 32032 个名字，80/10/10 划分）：

- bigram：train NLL **2.4543** / dev **2.4647**（几乎不过拟合，因为只有 27×27 个格子）
- bigram 采样会跑出不收敛的长串（如 `rielciylendumadepionyonera`）——
  它没有「名字快结束了」的全局感，只有局部转移概率。

## 3. MLP（Bengio 2003 风格）

结构：3 个上下文字符 → 各自查 10 维嵌入 → 拼成 30 维 → Linear(30→128) → tanh →
Linear(128→27) → 交叉熵。

关键洞察是**嵌入**：字符不再是 27 个无关的 one-hot 位置，而是被放进一个 10 维
连续空间，训练会自动让「语义/用法相近」的字符靠近（元音聚一堆）。泛化由此而来：
`("q","u","e")` 的经验和 `("k","i","e")` 能通过嵌入相似性互相借用，bigram 做不到。

实测（6000 步小批 SGD，lr=0.1，MPS 约 8 秒）：

- MLP：train NLL **2.2976** / dev **2.3087**，比 bigram 好 **0.156**
- 采样：`['naz', 'ele', 'lia', 'aldi', 'jarorsse', 'deza', 'smartai', 'rielcin']`——
  拼读像名字；bigram 采样里的跑串在 MLP 上概率被压下去了

## 4. 激活/梯度诊断（makemore 第 3/4 讲的核心方法)

训练完不是结束，要给网络做「体检」：

| 指标 | 实测值 | 怎么读 |
|---|---|---|
| 隐层 tanh 饱和度（\|h\|<0.01 占比） | 0.91% | 越低越健康；>30% 说明大量神经元"死"在饱和区，梯度传不动 |
| emb grad:weight 标准差比 | 0.0062 | 嵌入层梯度远小于权重——大量字符对是"稀有样本"，正常但提示学习率对它偏小 |
| fc1 grad:weight 比 | 0.0570 | 0.1 量级是健康区间（约等于每步更新 10% 的尺度） |
| fc2 grad:weight 比 | 0.0822 | 同上 |

这套"标准差比值"读法来自 makemore 第 4 讲：梯度太小（<1e-3）说明信号传不到，
太大（>1）说明训练不稳定——比只看 loss 曲线能更早发现问题。

## 5. 实现/踩坑要点

- **MPS 上 `torch.Generator` 是 CPU 对象**：`torch.randint(..., generator=g, device="mps")` 会炸。
  做法是 CPU 上采样索引再 `.to(device)`；`multinomial` 同理把概率搬回 CPU。
- 采样循环必须带 `max_len` 上限保护：欠训练模型可能长时间不吐终止符，`while True` 会挂死。
- bigram 的 dev 评测要用与 MLP 相同的 (prev,next) 对（block=3 数据集取最后一列即可），否则比较不公平。

## 6. 与后续章节的衔接

- T4/T5 的 GPT 本质上是本文 MLP 的「指数放大」：固定 3 字符窗口 → 任意长上下文，
  查表嵌入 → attention 动态聚合，输出端不变（全词表 softmax）
- 交叉熵 = NLL = softmax + 负对数，这三个词在后面章节会反复出现，现在就要等同起来
